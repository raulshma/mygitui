# i18n status (roadmap item 69)

The message-catalog seam (`src/lib/i18n`) is **wired end to end with English
only** — a proven path, not a translation effort.

What is wired:

- `t(key, vars)` resolves against the active catalog (fallback: English → the
  key itself); `{placeholder}` interpolation included.
- `appSettings.locale` (`"en"`, persisted under `mygitui.settings`) feeds
  `setLocale` on load and on every settings update. The Settings dialog
  exposes it under **Appearance → Language** (English + a disabled
  "More languages" placeholder — no other locales exist).
- Pilot call sites that already read through `t()`: ConfirmDialog default
  button labels (`action.confirm` / `action.cancel`), the Toaster's aria
  labels (`toaster.dismiss` / `toaster.repeated`), the ShortcutsOverlay title
  (`shortcuts.title`), and the CommandPalette placeholder
  (`palette.searchPlaceholder` + `common.noRepository`).

Deliberately deferred:

- **Full string rollout** until a second locale is actually wanted. `t()`
  reads the module-level active locale non-reactively (already-rendered views
  do not re-translate on a locale switch), so real locales want a reactive
  catalog first.
- **`describeError`'s user-facing strings** — they are assembled from raw
  engine error text (`git` stderr, IPC failure messages), which cannot be
  translated string-by-string; they need an error-code → message mapping
  instead. Kept out of the pilot to avoid entangling it with the error
  pipeline.
- **CI coverage gating** of any kind for translations (no key-completeness
  checks — the type system plus the key-fallback make missing keys visible
  without a CI job).
