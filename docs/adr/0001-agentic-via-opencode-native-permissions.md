# 0001 — Agentic AI via opencode's native permissions first; app-owned tool loop deferred

AI features are today single-shot: the UI pre-gathers context into character-budgeted prompts and deliberately neuters the opencode backend (the default), auto-rejecting every permission ask so it behaves as a plain text generator. We decided to make repo access agentic in phases: phase 1 stops auto-rejecting and instead forwards opencode's permission asks to the user as approvals, with an app-injected permission policy encoding the ceiling (reads auto-allowed except sensitive files; edits, shell commands, and other mutations ask; push/publish and non-repo network access denied). An app-owned tool loop over OpenRouter (AI SDK tool-calling) is deferred until OpenRouter parity actually matters — agentic features then degrade to single-shot on non-agentic paths rather than breaking.

Why: opencode already *is* an agent running in the repo directory on our default backend, so ask-forwarding is a permissions-plumbing change, not a new subsystem; the app keeps policy and UX control through permission rules and ask events while opencode owns the tool loop. Considered and rejected: an app-owned tool loop now (duplicates an existing agent runtime; opencode's session API cannot host foreign tool schemas, so it would be OpenRouter-only and immediately fork the experience); building both paths up front (two implementations to test before any value is proven).

Known tradeoffs, accepted at launch: `git log *` and `git diff *` stay auto-allowed, so `git log -p -- .env` can print COMMITTED secrets without an ask (the sensitive-name globs cover the usual secret filenames — `.env*`, `*.env`, key/certificate patterns, credential stores, `secrets/*`, in workspace-relative and absolute-path shapes — but a committed secret under any other name still flows through log/diff output; `git show` was dropped from the allowlist to close the direct blob read). The policy opens with a `{*, *, ask}` catch-all so unlisted actions (MCP tools, `todowrite`, …) ask rather than replaying the Build agent's `*` allow baseline.
